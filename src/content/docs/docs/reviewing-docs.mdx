---
title: Publishing Docs
name: "pulse-system-reviewing-docs"
description: "How a change to a Pulse docs page is drafted, reviewed and published through GitHub."
status: approved
---

1. A designer opens the page and selects **Edit this page**. This opens the file in GitHub's web editor, so no local checkout is needed.
2. They make the change and save it to a new branch as a pull request.
3. Someone else on the team reviews the change and approves it. Authors don't approve their own changes.
4. Merging the pull request into `main` makes Netlify redeploy the site, usually within a minute.

Merging a change doesn't make a page `approved` on its own. Each page's `status` (`draft`, `in-review`, `approved` or `deprecated`) is set deliberately, once the content has been reviewed for that purpose.

Everything on this site comes from its GitHub repository. There is no separate copy in Notion or Supernova to keep in sync.
